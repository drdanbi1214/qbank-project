# 합본3 풀이 임시작성 운영 문서

## 문서 목적

이 문서는 이단비 계정에 배정된 합본3 문항 풀이를 AI가 초안으로 만들 때의 고정 작업 기준, 자료 조사 기준, 저장 방식, 피드백, 실제 시범 작업 결과를 한곳에 기록한다.

목표는 단순 정답 해설이 아니라, 강의록·알렌·필요한 보조 자료를 활용해 해당 주제를 공부하는 사람에게 도움이 되는 풀이 초안을 만드는 것이다. 모든 결과물은 사용자가 검토하기 전까지 게시하지 않는다.

---

## 1. 절대 지켜야 하는 저장 원칙

1. AI가 작성한 풀이는 항상 임시저장으로만 만든다.
   - DB 기준: `drafts` 테이블, `target_type = solution`
   - `solutions` 테이블에는 넣지 않는다.
2. 임시저장 단계에서는 배정을 완료 처리하지 않는다.
   - 배정 상태를 `done`으로 바꾸지 않는다.
   - 사용자가 검토·게시할 때만 완료 처리 흐름을 탄다.
3. 기존 임시저장이 있으면 먼저 읽고, 사용자의 새 지시가 없으면 함부로 덮어쓰지 않는다.
4. draft 본문뿐 아니라 `metadata`에도 아래 정보를 남긴다.
   - 정답
   - 관련 강의록·알렌 링크와 페이지
   - 사용한 비행기 이미지 원본 파일명과 저장 경로
   - 모식도 출처와 저장 경로
   - 외부 검색을 했는지, 하지 않았다면 그 이유
   - 검토 상태 (`needs_user_review`)

## 2. 모든 풀이의 고정 도입부

풀이 본문의 첫 부분은 항상 아래 순서로 만든다.

1. 첫 줄: `안녕하세요 저공비행의삶입니다`
2. 첫 줄 글자 크기: `0.75em`
3. 바로 다음 줄: `비행기그림/` 폴더의 비행기 사진 1장
4. 비행기 사진 크기: 항상 `170px`

### 비행기 이미지 선택 규칙

- PNG, JPG, JPEG만 사용한다. HTML 파일은 제외한다.
- 매 풀이마다 무작위 순환 방식으로 고른다.
- 바로 직전 풀이에서 쓴 사진은 다음 풀이에 쓰지 않는다.
- 폴더의 이미지를 모두 한 번씩 쓴 뒤 다시 섞어서 순환한다.
- 사용한 원본 파일명은 `metadata.airplaneSource`에 기록한다.

## 3. 문체와 설명 방식

### 문체

- 풀이 본문은 반말로 쓴다.
- 대화체보다 정리형 종결을 우선한다.
  - 사용: `감소시킴.`, `증가할 수 있음.`, `따라서 답임.`
  - 피함: `감소시켜.`, `답이야.`
- 고정 인사말만 예외로 원문 그대로 사용한다.

### 인과관계 설명

기전이나 진단 과정은 한 문장에 몰아 쓰지 않는다. 다음처럼 줄을 나눠 화살표로 적는다.

```text
A가 일어남
→ B가 일어남
→ C가 일어남
→ 최종 결과가 나타남
```

### 기본 본문 구성

문항 성격에 따라 길이를 조절하되, 가능한 한 아래 순서를 따른다.

1. 정답
2. 핵심 개념 또는 기전
3. 그림 또는 모식도
4. 문제에 적용하는 인과 흐름
5. 선지별 판단
6. 직접 포인트는 아니지만 주제 전체를 이해하는 데 중요한 추가 내용 1~3개
7. 한 줄 암기 포인트

### 피해야 할 것

- 정답만 선언하고 끝내는 것
- 첨부한 강의록에 그대로 보이는 문장을 본문에서 다시 풀어 쓰는 것
  - 예: `강의록 근거: 10쪽에 … 명시되어 있음`처럼 반복하지 않는다.
- 단순히 큰 주제가 같다는 이유로 관련성이 약한 알렌·강의록을 붙이는 것
- 장식 목적의 이미지 또는 너무 많은 모식도
- 확실하지 않은 내용을 단정하는 것

## 4. 자료 탐색 및 첨부 기준

### 조사 순서

1. 문항에 이미 태그된 강의록에서 직접 근거가 되는 페이지를 찾는다.
2. 정답 약물·질환·기전을 직접 설명하는 다른 강의록 페이지가 있는지 전체 강의록에서 검색한다.
3. 모든 문항에서 알렌을 검색한다. 문항을 직접 설명하거나 주제 이해를 명확히 돕는 관련 단원이 있으면 본문 카드(`theoryEmbed`)로 첨부한다. 관련 단원이 없다면 억지로 넣지 않고 그 판단을 metadata에 남긴다.
4. 치료, 최신 권고, 기준값, 논쟁적 사실처럼 최신성·정확성이 중요한 경우 외부의 신뢰도 높은 자료를 검색한다.
5. 교과서적으로 명백하고 논쟁적이지 않은 사실은 매번 논문을 붙이지 않는다.

### 강의록

- 오답 선지를 배제하는 강의록뿐 아니라 정답 자체를 설명하는 강의록도 찾는다.
- 강의록 페이지는 본문에 페이지 이미지로 첨부한다.
- 관련 페이지가 스스로 충분히 설명되면 `강의록 근거`라는 별도 반복 문단은 쓰지 않는다.
- 여러 강의록을 붙일 때는 각 페이지의 역할이 겹치지 않게 한다.
  - 예: 한 장은 오답 선지 배제용, 다른 한 장은 정답 약물의 기전·부작용 설명용.
- **선지마다 근거 페이지를 따로 찾는다.** 정답 선지 하나만 설명하고 끝내지 않는다. 각 오답
  선지가 왜 틀렸는지 직접 뒷받침하는 페이지가 강의록 어딘가에 있는지 찾아본다. 한 강의록
  안에 흩어져 있으면 여러 쪽을, 서로 다른 강의록에 나뉘어 있으면 여러 문서를 함께 첨부한다.
  - 태그된 강의록 한 장으로 끝내지 말고, 그 강의록 전체와 필요하면 다른 강의록까지 넓혀
    선지 수만큼 근거를 모으는 것이 목표다.
  - 정말 근거를 못 찾은 선지가 있으면 억지로 만들지 말고 본문에서 "이 선지는 강의록에서
    직접 근거를 찾지 못해 일반 지식으로 판단함"처럼 그 사실을 밝힌다.
  - 찾은 페이지는 각각 `references`에 `label`로 "몇 번 선지 근거"를 구분해 남긴다.

### 알렌

- 문항을 직접 설명하는 관련 내용이 있으면 반드시 첨부한다.
- 카드를 붙이는 데서 끝내지 않는다. 해당 문서에서 이 문제를 이해하는 데 필요한 핵심을 1개의 표·인용 블록·텍스트 박스 중 하나로 재구성해 바로 읽을 수 있게 넣는다.
- 알렌의 정확한 하위 문서가 없고 상위 원문 한 문서에 내용이 들어 있으면 그 문서를 첨부하되, 본문에서 왜 관련 있는지와 핵심 내용을 짧게 정리한다.
- 관련 단원 정보는 draft metadata에도 함께 기록한다.

### 외부 검색과 모식도

- 외부 검색이 필요한 대표 상황
  - 치료 선택 또는 약물 비교
  - 최신 가이드라인, 권고 등급, 기준값
  - 최근 변경 가능성이 있는 검사·치료 알고리즘
  - 논쟁이 있거나 강의록만으로 답을 확정하기 어려운 내용
- 모식도는 핵심 기전과 직접 맞아야 한다.
  - 예: dopamine 작용 문항이면 일반 HPT axis 그림보다 dopamine의 TSH 억제가 표시된 그림을 우선한다.
- 모식도는 1~2개만 사용한다.
- 공공기관, NCBI, 학술 자료, 교과서형 공개 자료, Wikimedia Commons 등 출처와 사용 조건을 확인할 수 있는 자료를 우선한다.
- 그림 아래에는 원본 출처 링크를 작은 글씨로 남긴다.
- 단순 텍스트 코드 블록을 모식도 대신 사용하지 않는다.

## 5. 실제 작업 절차

### A. 대상 확인

1. 이단비 계정에 배정된 합본3 문항 중 대상 문항을 확인한다.
2. 계통·과목·단원·기존 강의록 태그·기존 임시저장을 확인한다.
3. 이미 본인 게시 풀이가 있거나 다른 사용자가 검토 중인 경우 새로 만들지 않는다.

### B. 내용 조사

1. 문제 줄기, 선택지, 현재 편집자 답을 읽는다.
2. 태그된 강의록의 해당 페이지를 찾고 실제 원본 PDF를 렌더링해 내용과 가독성을 확인한다.
3. 정답 약물·질환 이름으로 강의록 전체를 검색한다.
4. 알렌을 반드시 검색하고, 직접 연결되는 문서가 있으면 카드와 핵심 발췌형 설명을 함께 준비한다.
5. 최신성·치료·논쟁 여부를 판단해 필요할 때만 외부 근거를 추가한다.
6. 기전에 맞는 모식도가 도움이 되는지 판단하고, 필요하면 출처를 확인해 추가한다.

### C. 초안 작성

1. 고정 인사말과 170px 비행기 사진을 먼저 넣는다.
2. 정답을 먼저 제시한다.
3. 모식도와 `A → B → C → 결과` 인과 흐름으로 핵심 기전을 설명한다.
4. 선지별로 왜 맞고 틀리는지 짧고 명확하게 정리한다.
5. 정답과 직접 연결되는 추가 강의록과 알렌을 첨부하고, 알렌 핵심은 표·인용 블록·텍스트 박스로 본문에 다시 정리한다.
6. 해당 주제 전체 학습에 도움이 되는 중요 부가 내용을 적는다.
7. 한 줄 암기로 끝낸다.

### D. 저장과 검증

1. `drafts`에만 저장한다.
2. metadata에 답·참고자료·비행기·모식도·검색 판단을 기록한다.
3. 게시 풀이 수가 0개인지, 배정이 여전히 `pending`인지 확인한다.
4. 인사말, 170px 비행기, 반말 문체, 모식도, 태그 강의록 이미지, 알렌 카드와 알렌 핵심 발췌 블록을 확인한다. 직접 관련 알렌이 없을 때만 그 검색 판단을 확인한다.
5. 사용하지 않게 된 AI 업로드 이미지와 임시 파일은 참조 여부를 확인한 뒤 정리한다.
